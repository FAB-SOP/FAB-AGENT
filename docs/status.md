## 상세 기록

### CP① — 설계 점검

Phase 1의 AI 조사 기반을 바탕으로, 사람이 분석 결과를 검토하고 실제 업무와 기록으로 이어가는 과정을 개선 목표로 정리했다.

대상 사용자와 조사 과정의 불편을 정의하고, 조사 우선순위, 근거 중심의 원인 후보 검토, 담당자 협업, 선택 결과 추가 분석, 보고서·통계를 개선 범위로 정했다. 핵심 사용자 흐름과 인수조건, AI와 일반 시스템의 역할, 평가 목표도 함께 정리했다.

- **설계 근거:** 서비스 설계서 STEP 01 문제 정의, STEP 02 범위·성공 지표, STEP 03 사용자 여정, STEP 04 인수조건, STEP 05 AI 설계

### CP② — baseline 측정

개선 전 비교 기준으로 `phase1-end`를 지정하고, 동일 평가셋으로 개선 전후를 비교하기 위한 평가 조건을 정리했다.

**평가셋·모델·실행 횟수·baseline 결과**: 16.3/32

- **기준 버전:** `phase1-end` · `edd218a`
- **평가 근거:** 검증 결과서의 평가 환경·평가셋·개선 전 결과

### CP③ — 시나리오 통합

EV-1009를 기준으로 다음 한 사이클을 통합 점검 대상으로 정했다.

**사건·근거 확인 → 추가 질문 → 확인 요청 검토·승인 → 담당자 수락·회신 → 결과 선택·추가 분석 → 보고서 초안·검토·분류·확정 → 사건 종료**

결과 선택·요청 처리 화면과 Backend·Agent를 연결하고, 보고서 확정·사건 종료·요약 접수까지의 주요 코드를 반영했다. 관련 후속 보완이 포함된 `4c237c3`를 통합 점검 기준 버전으로 선정해 실행 흐름을 확인했다.

- **설계 근거:** 서비스 설계서 STEP 03 사용자 여정, STEP 04 인수조건
- **구현 근거:** PR #12 — 화면 연결, #15 — 보고서 확정·종료·요약 연결, #18 — Agent 결과 계약, #19 — 보고서 확정 후속 보완

### CP④ — 중간 점검

핵심 시나리오 연결을 바탕으로 우선순위 자동 평가·저장, 원인 통계 API·화면, 사용자 알림과 업무 결과 표시를 반영했다. Agent 결과의 저장·조회와 보고서 연결도 보완했다.

점검 이후에는 승인 대기와 현재 실행의 분리, 통합 대화 조회, 분석·질문별 업무 흐름 연결을 추가 구현했다.

- **구현 근거:** PR #13 — 통계 API, #16 — 우선순위 자동 평가, #20 — 통계 화면
- **후속 연결 근거:** PR #24 — 승인 대기·실행 분리, #25 — 통합 대화 API, #32 — 조사 블록·업무 흐름 화면
- **검증 근거:** 검증 결과서의 기능별 정상·예외·오류 처리 결과
