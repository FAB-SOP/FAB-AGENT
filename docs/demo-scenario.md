# 시연 시나리오 — 빈 DB로 띄워 서비스 흐름 전체 확인

> 이상이 생기면 → 무엇부터 볼지 정해 주고 → AI가 근거로 원인 후보를 좁히고 → 사람이 판단·승인해 다른 팀과 확인하고 → 그 결과로 다시 분석해 → 확정한 원인이 쌓인다.

시드(`backend/.../seed/SeedRunner.java`)는 현재 사건을 이상 이벤트 접수와 같은 경로로 등록한다(우선순위 평가 · 새 이상 알림 · 기본 분석). 판정과 분석은 평가 Worker와 Agent가 실제로 한다. AI 단계는 `ops/deploy/.env`의 LLM 키가 필요하다.

## 준비

```bash
./ops/deploy/deploy.sh down -v
```
```bash
./ops/deploy/deploy.sh up -d --build --wait
```

- 처음 1~2분은 시드 사건 4건의 기본 분석이 돈다. 계정 비밀번호는 모두 `fab1234!`
- 계정: `cmp.park`(CMP 엔지니어) · `etch.lee`(ETCH) · `cvd.kim`(CVD) · `mnt.jung`(설비정비팀) · `manager.choi`(관리자)

## 시드로 들어 있는 것

| 사건 | 상태 | 확인할 것 |
|---|---|---|
| EV-1006 · 1007 · 1009 | CMP 관리한계 이탈 · 우선순위 **상** · AI 기본 분석 | 우선순위 배지·사유, AI 원인 후보·근거·다음 단계, 추천 조치 |
| EV-1011 | CMP 단일 센서 짧은 편차 · 우선순위 **하** | 하 배지·사유 |
| EV-1018 · 1019 · 1020 · 1021 | 보고서 확정 · 원인 Man · Material · Method · Machine | 조사 보고서, 원인 통계 |
| EV-1022 | 보류 | 보류 사건 |
| EV-1023 | 타팀 확인 요청 승인 대기 (CVD) | 제안 검토·승인 |

## 흐름 점검표

| # | 단계 | 계정 | 화면 · 조작 | 기대 결과 |
|---|---|---|---|---|
| 1 | 감지 | cmp.park | 아무 화면을 연 채 `python3 ops/demo/send_anomaly.py` | 5초 안에 토스트 "새 이상 발생 · L012", 알림 종 배지 |
| 2 | 우선순위 | cmp.park | 이상 조사 목록 | 상(EV-1006·1007·1009) · 중(방금 L012) · 하(EV-1011). 배지를 누르면 판정 사유 |
| 3 | 원인 후보 | cmp.park | EV-1009 → 분석과 추가 질문 | AI 요약 · 다음 단계 · 원인 후보 지지/반증 · 근거(계측·센서·문서). 관측 근거 탭 센서 그래프 |
| 4 | 판단 | cmp.park | AI 추천 카드 "내 확인 목록에 추가" / 다른 팀 요청 카드 승인 | 카드가 그 자리에서 상태 변경, 단계 기록(채택 → 승인 → 발송) |
| 5 | 협업 | etch.lee (다른 브라우저) | 알림 종 → 확인·정비 요청 → 수락 → 회신 등록 | 요청자 쪽 알림 "회신 도착" |
| 6 | 다시 분석 | cmp.park | EV-1009 카드 아래 회신 체크 → 선택한 결과로 추가 분석 | 새 블록 "선택 결과 추가 분석" + AI 원인 분석 갱신, 쓴 회신은 다시 선택 불가 |
| 7 | 실패 유도 | cmp.park | 맨 아래 질문 칸에 근거가 없는 질문 | AI가 단정하지 않고 보류·추가 확인 필요로 답 |
| 8 | 확정 | cmp.park | 보고서 탭 → 초안 생성 → 검토 체크 · 원인 분류 → 확정 | 사건 종료, AI 요약 |
| 9 | 축적 | manager.choi 또는 mnt.jung | 원인 통계 | 4M 파이에 방금 확정한 사건 반영 (일반 엔지니어는 메뉴 없음) |

곁들여 볼 것: 추가 질문(승인 대기 중에도 가능), 내 할 일에서 수행 결과 기록, 제안 검토·승인(EV-1023), 참고 문서 검색, 종료 사건은 버튼 비활성.

## 다시 하고 싶을 때
- 알림만 다시: `python3 ops/demo/send_anomaly.py` (보낼 때마다 새 사건)
- 처음 상태로: 준비 단계의 `down -v` → `up`
